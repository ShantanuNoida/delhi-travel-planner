# Phase 2 — Multi-Agent QA System — Travel Itinerary Application (New Delhi)

## Context

This is **Phase 2** of the project already run by this team. Phase 1 stress-tested the travel application's itinerary **edit** capability and produced the document **"Itinerary edit commands QA"**.

Phase 2 stress-tests the application's ability to **answer questions** about an itinerary — reasoning, justification, and contingency handling — rather than modify it.

Reuse the same team name and the same agent structure from Phase 1. Do not rename the team or reassign roles.

## Carry-Over from Phase 1

- **Team name:** unchanged.
- **The 20 itineraries generated by Agent 2 in Phase 1:** reuse them exactly as-is. Do **not** regenerate, replace, or modify them. If they are not already in context, load them from the Phase 1 document.

## Team Structure & Responsibilities

### Agent 1 — Team Leader / Coordinator
- Unchanged from Phase 1.
- Owns the overall workflow and enforces the order of execution (Agent 3 → Agent 4 → Agent 5).
- Hands off outputs between agents and verifies each stage is complete before the next begins.
- Resolves conflicts or blockers between agents.

### Agent 2 — Itinerary Generator
- **No new work in Phase 2.** The 20 itineraries from Phase 1 are the fixed input for this phase.

### Agent 3 — Question Command Agent (NEW WORK)
- For **each of the 20 Phase 1 itineraries**, create and apply a total of **15 diverse question commands**.
- Questions must be **tailored to the actual content of that specific itinerary** — reference the real venues, days, and activities in it, not generic placeholders.
- Example question types (use these as inspiration, not an exhaustive list):
  - "Why was this `<venue>` chosen?"
  - "What if it rains?"
  - "What are the alternatives to `<venue>`?"
  - "What other activities can be done on Day 1 / Day 2?"
- Ensure diversity across question categories, for example:
  - **Justification** — why a venue, order, or timing was selected.
  - **Contingency** — weather, closures, holidays, crowds, transport disruption.
  - **Alternatives** — substitutes for a venue or activity.
  - **Expansion** — additional things to do on a given day or in a given area.
  - **Practicalities** — timing, cost, accessibility, travel between stops, best time to visit.
  - **Suitability** — fit for families, elderly travellers, solo travellers, dietary needs.
- Record every question issued and the application's full response to it.

### Agent 4 — Quality Manager / Product Manager
- Unchanged in role from Phase 1, now applied to **question responses** instead of edit responses.
- Evaluate the application's response to **every question command** issued by Agent 3.
- Identify:
  - **Loopholes** — questions the application ignores, deflects, misinterprets, or answers generically without reference to the actual itinerary.
  - **Inaccurate responses** — factually wrong details about venues, timings, closures, or travel; hallucinated places; contradictions with the itinerary itself or with earlier answers.
- For each issue found, write a **fix recommendation** and assign a priority: **High / Medium / Low**.
- Include a rationale for each priority assignment.
- Where relevant, note whether an issue also appeared in Phase 1 (recurring vs. new).

### Agent 5 — Documentation Agent
- Unchanged in role from Phase 1.
- **Append Phase 2 to the existing document "Itinerary edit commands QA"** — do not create a new file. Add a clearly marked **"Phase 2 — Question Commands"** section after the Phase 1 content, leaving all Phase 1 content intact.
- The Phase 2 section must include:
  1. Phase 2 objective and scope.
  2. Reference to the 20 carried-over itineraries (no need to reprint them in full — cite the Phase 1 section).
  3. The full list of 15 question commands applied per itinerary.
  4. The application's response/behavior for each question.
  5. Agent 4's findings: loopholes, inaccuracies, and fix recommendations grouped by **High / Medium / Low** priority.
  6. A summary with key takeaways, overall quality assessment, and a short **Phase 1 vs. Phase 2 comparison** (does the app handle edits or questions better, and which issues recur across both).

## Workflow (Phase 2)

1. Agent 1 kicks off Phase 2 and confirms the Phase 1 itineraries are loaded and unchanged.
2. Agent 3 creates and applies 15 question commands per itinerary (300 total) and logs application responses.
3. Agent 4 evaluates all responses and produces prioritized fix recommendations.
4. Agent 5 appends the Phase 2 section to **"Itinerary edit commands QA"**.
5. Agent 1 confirms completion of Phase 2.

## Deliverable

The updated document **"Itinerary edit commands QA"**, containing the original Phase 1 content plus a new Phase 2 section as specified above.
