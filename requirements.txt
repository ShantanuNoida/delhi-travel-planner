# Consolidated dependency file for Streamlit Community Cloud (and any other
# host that expects one requirements.txt at the repo root). Cloud always
# treats the repo root as the working directory, even though the app's
# entrypoint is phase6/app.py — see the per-phase requirements.txt files for
# local/offline-only dev dependencies not needed to *run* the deployed app.
#
# Excludes beautifulsoup4/nltk -- genuinely offline-only, used by
# phase1/scraper.py and phase1/chunker.py to build the index, never
# imported by anything the live app calls. Rebuilding the index from
# scratch is a local dev task; install phase1/requirements.txt for that.
#
# chromadb, sentence-transformers, and tqdm ARE needed live, despite being
# part of the same "Phase 1 indexing" module set -- real bug found via a
# live Cloud deploy (ModuleNotFoundError: No module named 'chromadb'):
# phase2/poi_search.py and itinerary_builder.py never touch ChromaDB (they
# read the pre-built pois.json/citation_index.json directly, as originally
# assumed), but phase4/explain_engine.py's RAG-question path
# (_rag_query -> phase1/embedder.py's query()) does -- it embeds the
# user's question at request time and searches the persisted
# phase1/data/chroma/ store, for any "why/what/how" question that isn't
# already answered directly from a stop's kb_* fields. Any question that
# reaches that path (most of them) crashed outright without this.
chromadb>=0.5.0
sentence-transformers>=3.0.0
tqdm>=4.65.0
#
# Also excludes pyaudio, pyttsx3, pygame — server-side mic capture and
# local-speaker TTS playback, both meaningless on a remote host (there's no
# "server microphone" that belongs to a remote user, and TTS output already
# goes through edge-tts + st.audio() for in-browser playback, not pygame).
# The app already degrades these to "please use the text box instead" on
# any failure (phase6/voice_input.py), so dropping them from the cloud
# install just avoids a fragile pyaudio/PortAudio build for a feature that
# couldn't work remotely regardless.
#
# reportlab (not python-docx) generates the emailed/downloaded itinerary as
# a .pdf -- pure-Python wheel, no LibreOffice/MS Word conversion step
# needed on a remote host. pypdf is test-only (phase6/test_phase6.py reads
# the generated PDF back to assert on its content) but is small enough to
# just keep in the one shared requirements file rather than add a second.
streamlit>=1.35.0
reportlab>=4.0.0
pypdf>=4.0.0
pandas>=2.0.0
pydeck>=0.9.0
requests>=2.31.0
python-dotenv>=1.0.0
openai>=1.0.0
edge-tts>=7.0.0
SpeechRecognition>=3.10.0
#
# Pinned below 2.0 -- real bug found via a live Cloud deploy
# (ModuleNotFoundError: No module named 'mcp.server.fastmcp'): mcp 2.0.0
# dropped FastMCP entirely in favor of a new MCPServer class, an
# unannounced-in-code breaking change. phase2/poi_search.py,
# itinerary_builder.py, weather.py, and travel_time.py all instantiate
# FastMCP(...) unconditionally at import time (only used for their
# standalone `python poi_search.py` MCP-server mode, never called by the
# live app), so any 2.x resolve crashes the app before it can even start.
mcp>=1.0.0,<2.0.0
